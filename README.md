# 德州扑克 SNG 锦标赛（单机版）

9 人单桌 Sit & Go 德州扑克锦标赛：你 + 8 个风格化 AI，完整真实比赛规则，内置实时分析辅助工具（胜率、对手范围推断、底池赔率/EV、ICM、行为统计 HUD、翻前范围表、逐街复盘与赛后分析）。

纯前端单机，无服务器；`npm run release` 产出单文件 HTML，双击即玩。线上版可"添加到主屏幕"全屏打开、离线可玩。

## 移动端

布局由 `ui/layout.ts` 判定并写到 `<html data-layout>`，CSS 与组件读同一个来源：

| 布局 | 条件 | 形态 |
|---|---|---|
| 桌面 | 其余情况 | 原样：宽桌 + 右侧常驻辅助面板 |
| 竖屏 | 竖放且宽 ≤ 1024px（手机、竖放平板） | 高椭圆牌桌，座位按开局人数均匀排布；行动条一排大按钮，加注两步（额度面板 → 确认）；顶栏只留加速与菜单 |
| 横屏 | 横放且高 ≤ 520px（横放手机） | 宽桌在左，点评与竖排行动按钮在右侧拇指区 |

触屏布局下，牌桌上英雄旁只显示胜率小标签，点开是底部面板（拖把手切半屏 / 全屏、下拉关闭；横屏为右侧抽屉），四个辅助页签全部保留；设置、范围表、离开牌桌收进菜单面板。弹窗改为贴底面板，大厅主按钮贴底。

## 命令

```bash
npm install
npm run dev      # 开发（http://localhost:5173）
npm test         # vitest 全量测试（引擎规则/评牌器/equity 基准/AI 策略/对手建模/ICM/fuzz 不变量）
npm run build    # tsc 类型检查 + vite 单文件构建
npm run release  # 构建并输出 release/德州扑克SNG.html（file:// 双击可玩）
npm run calibrate -- [style] [games]   # 测某风格 AI 的实测行为统计（调参 / 重校 ai/adapt.ts 的 REF）
npm run build:web  # web 版 → dist-web/：同一个单文件页面 + manifest / 图标 / service worker
npm run icons    # 由 public/icons/icon.svg 重新渲染 PWA 图标（依赖本机 Chrome）
npm run deploy   # 测试 → build:web → rsync dist-web/ 到服务器（线上：https://47.109.97.108/poker/）
```

## 部署

与饮食日记、叠叠中国、同路同机（阿里云轻量服务器，nginx 根目录 `/var/www`，每个项目一个子目录）。

- 目标写在根目录 `.deploy.env`（已 gitignore）：沿用 `nutri/.deploy.env` 的 SSH 目标，`POKER_PATH=/var/www/poker`、`POKER_URL=https://47.109.97.108/poker`
- nginx 规则见 `scripts/nginx-poker.inc`（已粘进服务器 `/etc/nginx/conf.d/nutri-site.inc`）：`index.html`、`sw.js`、`version.json` 设为 `no-cache`，发版后刷新即是新版本；manifest 指定 `application/manifest+json`
- PWA：service worker 安装时预缓存全部产物（不到 1MB），页面导航网络优先、断网回退缓存；单文件版（`release/`）不注入任何安装标签，保持零外部引用
- 存档在浏览器 localStorage（键 `poker-save-v1` / `poker-prefs-v1`），换设备不互通；与同域名下其他项目键名不冲突

## 玩法

- 买入 100。大厅可选赛制：**人数** 9 人（前三名 50/30/20）/ 6 人（前两名 65/35）/ 单挑（赢者全拿）；**结构** 标准（1500 起始、每 9 手升盲）/ 快速（每 5 手）/ 深筹（3000 起始、每 12 手）
- 盲注按手数升级（后期含 ante），打到只剩 1 人
- 快捷键：`F` 弃牌 / `C` 过牌·跟注 / `R` 加注（滑条定额）/ `A` 全下
- 顶栏可切换：加速、风格标签、隐藏辅助（纯净模式）、音效
- **推断模式**（大厅 / HUD / 复盘可切）：上帝视角 = 范围推断借用每个 AI 的真实策略函数；诚实模式 = 只用你在牌桌上能观察到的行为统计（以紧凶为先验），更接近真实对局的训练。AI 自身的决策不受该开关影响
- 进度在手与手之间自动存档（localStorage），大厅可继续或复盘；偏好（赛制/阵容/推断模式）单独保存

## 辅助工具

| 工具 | 说明 |
|------|------|
| 实时胜率 | Web Worker 蒙特卡洛（增量收敛，上限 40 万次）；河牌/窄范围自动切精确枚举（标"精确"） |
| 对手范围 | 13x13 热力矩阵：按每个 AI 的风格策略函数对其行动线做贝叶斯收窄，与 AI 实际决策共用同一 policy，推断天然一致 |
| 赔率 & EV | 底池赔率、跟注所需胜率、跟注/弃牌 EV 对比条；诈唬盈亏平衡弃牌率 |
| ICM | 跟注可能被淘汰时，额外给出奖金口径（Malmuth-Harville）的所需胜率；筹码可跟、ICM 不可跟时明确提示 |
| 数据 | 全桌实时行为统计（VPIP / PFR / 3bet / AF / c-bet / 面对下注弃牌率 / WTSD），以及"AI 眼中的你"画像 |
| 翻前范围表 | 按位置的开牌 / 面对开牌（跟注·3bet）频率表——就是紧凶 AI 实际使用的策略表，当前手牌高亮 |
| 观察员 | 每次出手后以职业牌手观战口吻点评一句（桌面顶栏 🎙️ / 手机菜单里开关）：借用棋类注解 !! 妙手 / ! 好棋 / !? 趣着 / 本手 / ?! 疑问手 / ? 恶手 / ?? 败着。依据紧凶基准频率、对推断范围的胜率 vs 赔率、ICM、牌力 × 纹理、尺度、对手风格；只用当时可知的信息，不做结果论。点评随手牌存档，复盘时按游标显示 |
| 复盘 | 每手事件溯源记录，逐街回放 + 上帝视角 + 当时胜率快照 + 范围推断随游标重算（可切诚实模式）；一键导出 PokerStars 风格手牌历史（.txt，可选含全部底牌） |
| 赛后分析 | 比赛结束自动生成（固定规则、确定性）：统计 + 红蓝线（累计盈亏拆成摊牌/非摊牌）+ 跟注/弃牌决策 EV 损失 + 翻前相对基准的松/紧偏离 + 负赔率跟注 / ICM 泡沫期漏洞 / 错失价值 / 短码漏推 / 诈唬与被诈唬 / bad beat 等诊断 |

## AI 陪练

大厅可选两套阵容：

- **传奇桌**（默认）：扑克史知名选手的打法致敬版，各自独立参数——艾维🦁（全能）、毒王德万🔥（超凶）、赫尔穆斯👑（极紧）、丹牛🎯（小球）、布朗森🤠（老派凶）、Isildur⚡（疯狂）、陈强尼🐉（稳凶）、昂格尔☄️（天才凶）
- **风格桌**：基础五风格——紧凶🦈 / 松凶🐺 / 岩石🗿 / 跟注站🐮 / 疯鱼🐙

AI 的决策 = 策略分布 π(action | 风格, 公开局面, 手牌) + 一组有界精修 + 种子化采样：

- **翻前**：按位置的 169 类频率表（`ai/preflopRanges.ts`，现代 9 人桌打法），面对开牌时读开牌者位置与尺度；风格的松紧沿 `ai/handRanking.ts` 的强弱顺序展开/收窄，因此"A5s 开、A6o 不开"这类结构在任何松紧下都保留。短码（≤10bb）切 push/fold 近似 Nash 表（含 ante 修正）。
- **翻后**：7 个牌力桶 × 局面（是否有位置、是否持有主动权、上街是否开火、SPR、牌面湿度、面对注额相对底池的尺度）。连续下注（barrel）是显式建模的：上街开火后本街继续的概率显著高于独立采样。
- **下注尺度**只由街 / 纹理 / SPR / 风格决定，不随牌力变化——不会用尺度泄露牌力。
- **对手建模**：只用公开行为统计（`analysis/playerStats.ts`），对人类玩家以紧凶为先验、按样本收缩推导动态风格（`ai/adapt.ts`）。你疯打，AI 会更多抓诈；你被动，AI 会更多施压。面对高频诈唬者少弃、面对高频 3bet 者少弃。
- **ICM**：面对可能被淘汰的跟注和自己的推全下，按奖金口径的风险溢价收紧（`analysis/icm.ts`）。
- **有界精修**：实时 equity（±30%）、顶对弱踢脚、对手模型、ICM 都只在 policy 分布上做有界偏移，所以范围推断（用同一 policy 反推）与 AI 行为保持一致。

范围推断面板能直接读出每个人的倾向差异。

## 架构

```
src/core      纯 TS 牌局引擎（发牌/下注状态机/边池/摊牌/锦标赛层），事件溯源
src/analysis  范围(1326组合加权)/equity(MC+精确枚举)/贝叶斯推断/强度分桶/纹理/EV/ICM/行为统计/赛后分析
src/ai        风格参数/手牌排序/范围记法/翻前频率表/push-fold/策略函数π/决策/动态风格
src/workers   equity worker（?worker&inline，兼容单文件构建）
src/store     gameController(主循环)/opponentModel(对手模型)/viewModel(事件→视图)/replay/storage(存档+偏好)/handHistoryExport
src/ui        React 组件（牌桌/行动条/HUD/范围矩阵/复盘/大厅）
scripts       calibrate.ts：风格 AI 行为统计校准
tests         评牌器对拍/规则剧本/equity 基准/翻前表与策略方向性/对手建模/ICM/AI 统计/fuzz 不变量
```

分层铁律：`core` 不依赖任何上层；`analysis` 与 `ai` 互相引用但**无文件级循环**（`ai/policy` 用 `analysis/buckets`，`analysis/inference` 用 `ai/policy`——这是"推断与决策共用一个策略函数"的设计核心）；三层均不含 DOM；UI 只经 `store` 消费引擎。引擎无时间概念，动画 = 事件流回放。所有随机数来自种子化 mulberry32，复盘确定性重算。

**policy 是支点**：`ai/policy.ts` 的 π 同时驱动 AI 决策（`ai/decide.ts`）和范围推断（`analysis/inference.ts` 贝叶斯反推）。改策略时两边自动一致；decide 里的精修都必须有界。
